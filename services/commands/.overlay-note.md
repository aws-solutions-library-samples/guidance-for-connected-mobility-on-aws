# `_lib.fleet_membership` Overlay Pattern for Commands Lambda

This note documents how `_lib.fleet_membership` is made available to the commands Lambda
at deploy time, the pattern used by the Sim Lambda as prior art, and what Group 2 Task 2.2
must replicate in `deployment/stacks/commands_stack.py`.

See spec § Design § 6 (Shared `_lib.fleet_membership` overlay pattern) for the authoritative
design decision.

---

## (a) Source Location

`_lib.fleet_membership` lives at:

```
services/connectors/oem1/_lib/fleet_membership.py
```

This is the **single source of truth** for all three shared helpers used by both the Sim
Lambda and (once Task 2.2 ships) the Commands Lambda. Do NOT copy this file directly into
`services/commands/` — that would create a duplicate that diverges silently. The CDK bundle
helper is responsible for the copy at asset-staging time only.

---

## (b) How the Sim Path Overlays It

### Test-time (conftest.py)

`services/simulation/lambda/conftest.py` inserts the connector package root into
`sys.path` so that `import _lib.fleet_membership` resolves during local pytest runs
without duplicating the source:

```python
# services/simulation/lambda/conftest.py, lines 19-23
_CONNECTOR_ROOT = os.path.normpath(
    os.path.join(os.path.dirname(__file__), "..", "..", "connectors", "oem1")
)
if _CONNECTOR_ROOT not in sys.path:
    sys.path.insert(0, _CONNECTOR_ROOT)
```

This `sys.path.insert(0, _CONNECTOR_ROOT)` line is the authoritative test-time resolution
mechanism. It resolves `_lib.fleet_membership` to `services/connectors/oem1/_lib/fleet_membership.py`.

### Deploy-time (CDK bundle helper)

`deployment/stacks/simulation_stack.py` defines `_bundle_sim_lambda()` (lines 95–128), which:

1. Copies `services/simulation/lambda/` into a clean build directory (`.build/sim_lambda/`).
2. Overlays `services/connectors/oem1/_lib/` at `_lib/` inside the staged asset via
   `shutil.copytree(_CONNECTOR_LIB_SRC_DIR, os.path.join(dst, "_lib"), ...)` (line 121).
3. Returns the staged asset path for `lambda_.Code.from_asset(...)`.

The key `copytree` call (simulation_stack.py lines 121–124):

```python
shutil.copytree(
    _CONNECTOR_LIB_SRC_DIR,
    os.path.join(dst, "_lib"),
    ignore=shutil.ignore_patterns("__pycache__", "tests", "*.pyc", ".pytest_cache"),
)
```

> **Note on CDK-side overlay history**: this bundle helper was introduced in commit
> `6bd5b1ef` (spec `2026-08-31-cms-sim-api-fleet-scoping`). If a reviewer cannot locate
> the `_bundle_sim_lambda` function in the current tree, check that commit.

---

## (c) Commands Lambda Must Adopt the Same Pattern

Per spec § Design § 6, `deployment/stacks/commands_stack.py` must replicate the Sim
bundle helper before the `lambda_.Code.from_asset(commands_asset_path)` call:

1. Copy `services/commands/` into a clean build directory.
2. Overlay `services/connectors/oem1/_lib/` at `_lib/` inside the staged asset using
   `shutil.copytree(..., dirs_exist_ok=True)` (idempotent).
3. Pass the staged asset path to `lambda_.Code.from_asset(...)`.

A matching `conftest.py` must be added at `services/commands/conftest.py` with the same
`sys.path.insert(0, _CONNECTOR_ROOT)` pattern so local pytest runs resolve `_lib.fleet_membership`
without duplicating the source.

**Implementation lands in Group 2 Task 2.2** — see spec § Design § 6 and tasks.md Group 2.

Do NOT copy `fleet_membership.py` into `services/commands/` as a source-tree file. The
overlay is CDK bundle-time only.

## (d) Helper Signatures Verified Live via `inspect.signature`

The following signatures were captured live against
`services/connectors/oem1/_lib/fleet_membership.py` using:

```bash
python3 -c "
import sys; sys.path.insert(0, 'services/connectors/oem1')
from _lib.fleet_membership import classify_driver_self, resolve_vins_to_fleets, parse_fleet_ids
import inspect
print('classify_driver_self:', inspect.signature(classify_driver_self))
print('resolve_vins_to_fleets:', inspect.signature(resolve_vins_to_fleets))
print('parse_fleet_ids:', inspect.signature(parse_fleet_ids))
"
```

**Raw output**:

```
classify_driver_self: (claims: dict, driver_self_enabled: bool = True) -> Tuple[bool, str]
resolve_vins_to_fleets: (vins: list[str], ddb_client=None, table_name: str | None = None) -> dict[str, str]
parse_fleet_ids: (claims: dict) -> set[str]
```

Note that `resolve_vins_to_fleets` carries two optional test-injection parameters
(`ddb_client` and `table_name`) not shown in the spec's abbreviated signature — these are
used by tests to pass a moto DDB fake and an explicit table name without environment
variables. Commands Lambda usage passes no keyword args (relying on the env var
`FLEET_ENROLLMENT_TABLE_NAME`), exactly as the Sim Lambda does.
